# 页面与内容模板

> **2026-09-10 最新展示规则：游客与登录态头部互斥。** 游客显示原三个数字指标，登录后统一显示 WELCOME, VOYAGER 欢迎与个人身份状态（实际身份在角色标签显示）；两块不叠加。五个一级 Tab 在移动端恢复紧凑原图形＋文字 Logo；二级及更深页面无 Logo；桌面/横屏统一侧栏保留品牌，内容区不重复。Intel 列表、新闻详情及 Updates 中的新闻条目保留作者头像（紧邻昵称）和图片。Dashboard 内容池采用已确认的四类 Updates 与两类 Events。




版本 2.3 · 2026-09-09 · 从属于 [权威 UI 规范](../design-system.md)，组件尺寸见 [组件说明](ui-components.md)。

本文件定义改版目标，保留既有业务与路径。效果图中的姓名、日期、世界、活动、数字是示意数据，不得直接写入产品。

## 1. 产品与信息架构

Multiverse Collective 将内容、社群、参与活动与 Multiverse Console 硬件连接起来。五个主入口分别回答一个问题：最近发生了什么、有什么情报、设备进展如何、可以观察和参与哪些世界、我与其他成员是谁。

| 主入口 | 根路径 | 核心内容 | 次级归属 |
| --- | --- | --- | --- |
| Dashboard | `/console` | 最近动态 + 参与入口 | 不承载个人资料管理 |
| Intel | `/intel` | 公告/情报文章与讨论 | Intel 详情、Voting Hub `/vote` |
| Devices | `/devices` | 当前设备观察、批次、进展与讨论 | 设备详情、批次详情、领取、我的设备 |
| Worlds | `/worlds/live` | 世界观察、队列、投递与交流 | `/worlds` 档案、详情、提交、Signal |
| Voyagers | `/voyagers` | 成员与身份 | My Profile `/profile`、Logs、Voyager Path |

五个一级入口统一呈现紧凑品牌＋必要操作（若有）→ 内容；不再显示重复 Tab 名称；二级列表、详情和任务页不显示 Logo，直接使用紧凑返回/任务栏。该规则在浏览器、PWA、未来 App 中相同。具体尺寸见主规范 §1.3；路由层级、底栏显示、来源返回和退出规则见 [导航与交互合同](interaction-contracts.md)。

以上是目标导航归属，需在共享映射中实现；现有前缀判断未必覆盖所有次级路径。根 tab 激活不意味着改变地址或合并数据。独立获客、支付回跳、认证、后台有自己的流程壳；不要为了统一在所有页面机械显示五项底栏。

## 2. Dashboard：最近发生什么、现在能参与什么

参考：[正式结构图](reference/dashboard-updates-events.png)。

### 阅读顺序

1. 一级必要操作区 → 三项数字看板 → Updates；Dashboard 名称仅作为 sr-only h1，不显示标题行或其留白。尺寸按主规范 §1.3；真实日期可放内容区。
2. 标题栏下 16px 进入 **Updates** 标题 + 最近 10 条提示 → 纵向时间轴。
3. **Events** 标题 → 横向可参与活动卡片。
4. 固定在视口底部的 Quiet Rail，Dashboard 选中。

不增加巨大 hero、欢迎横幅、个人积分、等级条带或 My Profile。My Profile 和头像快捷入口属于 Voyagers。旧图的 My Profile、Home、两列 Actions 网格均作废。

### Updates 内容合同

- 固定最多 10 条，按发生时间由新到旧；不足时显示实际数量，不能补假事件。只允许 Intel、Voyager Activated、Established World、Device Update。
- Intel 的 NOTICE / DEVICE / ORG 都有资格进入，不设置子类型保留位。Classified 对游客显示锁定卡，详情继续拦截正文。
- Voyager Activated 最多 2 条且只保留 7 天内；Established World 最多 3 条且每个世界只出现一次；Device Update 按设备去重。应用分类上限和实体去重后，再取全局最新 10 条。
- 标题说清发生了什么；类型和时间辅助理解，说明不重复标题。来源链接指向真实详情，无目标时不假装可点击。
- 时间轴独立一列；有图固定左图右文；无图或图片加载失败时，正文从内容区左侧开始占满剩余宽度，不渲染替代图标、占位图片或空缩略图列。390px 时缩略图 120×64，间距 12px，文字不能缩至 12px 以下。
- 「8 条图文 + 2 条纯文」只属于示例，不是数据配额。真实比例由事件决定。
- 不展示评论计数与一排行内动作，不把每条动态做成厚重卡片。10 条通过页面纵滚阅读；不会全部塞进 844px。

### Events 内容合同

- 横向活动集合，完整主卡 + 下一张露出；保持横向轨道，宽屏可多显示几张但不改双列网格。
- 卡片只包括 Vote Open 与 Signal Tuning。两类各最多 3 个并交错排列；其他长期入口留在所属页面。
- Vote 必须 active 且未到期，优先即将截止的 3 个；登录后隐藏已完成或无资格的项目。
- Signal Tuning 必须处于当前开放轮次，按实际开放时间取最新 3 个；登录后只保留当前用户尚可参与的世界。
- 游客可以看见全部开放卡片；点击后在目标流程登录并返回原任务。已结束项目不作为开放活动展示。
- 活动可以对应已出现在 Updates 的事件：Updates 告诉发生了什么，Events 提供当前参与途径；标题和说明避免机械重复。
- 刷新、网络错误、无活动、权限不足、卡片媒体失败独立处理。一个轨道失败不隐藏另一个区块。

### 顶部数字看板

保留原有 Parallel Worlds / Devices / Voyagers 三项数字及点击展开／再次点击收起说明的交互。数字看板是产品内容，不属于被移除的重复 Tab 标题。顺序固定为 数字看板 → Updates → Events；不恢复 Dashboard 大标题或个人资料入口。

使用新版 ArchiveStatStrip：三等分、品牌橙数字、Courier Prime、深蓝平面底、细边框；标签至少 12px，可换行，点击目标至少 44px。不得恢复旧光效、装饰框或旧版表单样式。统计失败显示“—”和独立重试，不显示假的 0，也不阻断 Updates / Events。

统计口径不变：世界数沿用原世界记录计数，Voyagers 沿用原已注册 Voyager / Applicant / Architect 计数 × 1.7 向上取整的展示规则，Devices 保留“?”，不改成设备批次数。展示数量不能替代成员列表的实际人数。iOS 缓存服务端已计算的看板值，离线沿用同步时间；旧缓存或未缓存时保留看板和未知值，不将离线列表长度当作全量统计。

### 首屏与验收

390×844 首屏应看见数字看板、Updates 起始内容和底栏，不显示重复 Dashboard 标题；不要求 Events 同时出现。本轮不增加顶部 Events 跳转，Updates → Events 顺序不变。图中长图只画一次底栏，实际固定于视口，而不是作为长列表尾部普通行。验证所有 10 条可读，最后一张活动的按钮不被固定底栏遮挡。

## 3. Intel：清楚的内容层级与阅读

参考：[Intel 视觉稿](reference/intel.png)。

### 页面顺序

一级必要操作区 → 类型图例 + 次级 Voting Hub 入口（无重复 Intel 标题） → ALL / PUBLIC / CLASSIFIED 筛选 → 重点文章（若真实存在）→ 最近文章轻列表 → 加载更多/分页。

- 重点内容可用较大标题或媒体区，但不额外复制成下面第一条重复文章。没有策划重点时直接列近期内容。
- 分类、标题、简短摘要、发布时间/作者为主要字段；评论数量只有在数据真实且有助浏览时出现。
- PUBLIC / CLASSIFIED 是既有可见性含义，不能为了漂亮取消限制、提前下发不可见正文或用假锁掩盖权限漏洞。
- Voting Hub 是 Intel 内的次级入口，不增加第六个底 tab。

### 详情模板

紧凑返回栏（上下文 Intel）→ 分类与完整文章标题 → 作者/时间 → 正文媒体 → 相关文章（如真实存在）→ 讨论。正文 16px，阅读宽度最大 720px；只有一个 h1。必要阅读内容不能用折叠和省略号藏掉。

筛选无结果、文章已删除、无权限、评论失败、媒体失败各有状态。返回恢复筛选和列表位置，不跳回无关根页。

## 4. Devices：设备档案、观察与履约进展

Material Records 位于 INFO 内的 FAQ（Before You Claim）上方。所有素材条目在统一页内弹窗查看，图片完整等比显示，视频在弹窗内播放；不跳转原始文件或打开新标签。关闭后恢复原列表位置及触发条目的焦点。

参考：[已选 Devices 风格](reference/devices-style.png) 与 [组合稿](reference/devices-selected-nav.png)。组合稿中的 HOME 已失效。

### 页面顺序

一级必要操作区 → 既有档案入口（无重复 Devices / Device Archive 标题） → 批次选择 → 观察媒体 → 来源/抓帧时间/真实状态 → 与当前设备有关的单个行动区 → INFO / UPDATES / DISCUSSION → 对应内容。

- 当前实现的三个内页签是 **INFO / UPDATES / DISCUSSION**；不要被旧说明或 Worlds 模式改成 Live Chat。默认 Info。
- 批次切换同步该批次媒体、信息、进展、讨论上下文；不能只改标题而保留另一批的价格或图。
- 最近画面不等于直播。明确 RECENT FRAME / VIDEO / LIVE / OFFLINE，并有真实来源和时间。
- 产品轮廓按原图，最新型号按 [设备素材库](../device-reference/README.md)；不将生成图中错误硬件当成正式产品。

### 行动与进度

已拥有设备时显示相关进展与查看详情；未拥有时仅在真实可领取/购买且当前用户符合条件时显示相应动作。价格、库存和 claimOpen 依据实际业务，不从样例写死。

进度是有序阶段与一条当前说明，不是四张彩色指标卡。阶段名称与状态先核对订单/批次源；失败、暂停、尚未开始不能都当「处理中」。完整履约解释保留在详情，不在总览堆所有订单字段。

### 次级页面

- `/devices/[id]`：设备身份、原始媒体、状态、事实信息、相关批次与适用操作。
- `/devices/batches/[slug]`：批次故事、阶段、关键更新、相关设备和讨论入口。
- `/devices/batches/[slug]/discussion`：完整讨论与输入，保留批次上下文。
- `/devices/claim` / success：专注领取流程，明确条件、结果、返回，不在视觉改版中制造真实订单。
- `/devices/my-consoles`：用户真实拥有设备列表；无设备给适当入口，不补展示假设备。

## 5. Worlds：观察、队列与世界档案

初始 Worlds 图只参考媒体和内容关系，旧导航不采用。业务模式依据 [实时观察房间](../product/live-observation-rooms.zh.md) 与当前页面。

### 默认观察页

一级必要操作区 → 世界档案入口（无重复 Worlds 标题） → 当前观察媒体 → 世界名、来源与真实状态 → **QUEUE / DISPATCH / LIVE CHAT** → 当前面板。默认 Queue。

- 观察区清楚区分视频、直播、最近抓帧、离线；不能永远亮绿点写 LIVE。
- Queue 表达真实排队和处理状态。等待用户选择与已提交排队不同，处理中不等于队列中所有条目都在执行。
- 容量来自配置；即便当前产品文档有 50 的容量，也不能写死进通用 UI 组件。预计 8–10 分钟等业务估计不能被画成准确倒计时。
- Dispatch 使用有说明的表单/Sheet；用户看见描述、所需材料、当前可提交性和提交结果。切换面板、失败后保留草稿。
- Live Chat 与通用讨论共用正文、头像、输入和反馈语法；实时能力不等于虚构在线人数。

### 世界档案与详情

`/worlds`：真实重点世界 + 分类/筛选 + 轻列表/媒体卡；`/worlds/[id]`：世界名、媒体、叙事与状态、作者、相关记录、可用参与操作。普通档案不复制实时房间的队列控制。

`/worlds/submit`：专注提交模板；`/signal`：信号证据、当前问题/选择、一个主要操作。保留权限和审核状态，不把已提交 UI 当作已批准发布。

## 6. Voyagers：成员、身份与 My Profile

参考：[Voyagers 视觉稿](reference/voyagers.png)。

### 页面顺序

一级必要操作区 → **My Profile** / Voyager Logs 次级入口（无重复 Voyagers 标题） → 有真实编辑依据的重点成员/Architect 内容 → 批次或成员筛选 → 成员列表 → Voyager Logs 入口。

- My Profile 在 Voyagers 明确可发现；未登录显示与鉴权一致的登录/申请引导，不能让用户误以为存在资料。
- 重点 Architect 是内容策划位置，不必永远有一张同一人物卡。无重点时正常列表即可。
- 成员列表的姓名、头像、角色、批次均来自真实数据，效果图人物不得当生产种子数据。
- 「我的资料」与「成员公开资料」不是同一路径语义；没有他人详情功能时不要生成假链接。

### 个人资料与成长路径

`/profile`：返回实际来源（无来源回 Voyagers）+ My Profile 紧凑标题栏 → 当前身份 → 可编辑字段 → 保存/结果 → 必要账户项。编辑未保存提示明确；敏感账户动作与公开展示分开。个人资料在导航上归属 Voyagers，不迁回 Dashboard。

`/voyager-path`：无 Logo 的返回标题栏 → 当前阶段 → 已完成证据 → 下一步 → 后续阶段。避免堆统计面板。身份提升、设备进展可关联但不混成一个没有解释的总百分比。

`/logs` 是二级列表：无 Logo → 返回来源（无来源回 Voyagers）+ Voyager Logs 标题 → 筛选/成员创作列表。`/logs/[id]` 是正文详情：无 Logo → 返回来源（无来源回 Logs）→ 日志完整标题/正文/讨论。两者归属 Voyagers；从 Dashboard 打开正文时返回 Dashboard，不能因归属改变访问历史。数据权限和编辑动作保持既有规则。

## 7. 其他页面模板

| 模板 | 核心阅读顺序 | 主要约束 |
| --- | --- | --- |
| 登录/注册 | 可选品牌展示 → 当前任务 → 字段 → 主动作 → 替代路径 | 需要身份识别时保留 logo；16px 输入、错误保值、真实 redirect |
| 认证过期/回跳 | 紧凑任务标题 → 原因/下一步 | 不自动重复品牌，不影响恢复原任务 |
| 申请/quiz/投票/signal | 紧凑任务标题 → 进度 → 问题/证据 → 选择 → 一个主动作 → 结果 | 单步专注，前后步骤保留答案，不用五张等权卡抢主次 |
| 领取/支付回跳/成功 | 紧凑任务标题 → 对象与条件 → 关键确认 → 真实状态 → 下一步 | 提交成功与支付/履约成功区分；不伪造成功页 |
| 提交/编辑表单 | 紧凑任务标题 → 页面目的 → 分组字段 → 附件 → 保存/提交 | 保存草稿与正式提交含义明确 |
| 公共介绍/投资资料 | 产品叙事 → 证据与媒体 → 下一步 | 可用更大排版，但不变品牌、logo；不机械套应用底栏 |
| Studio / Worldflow | 紧凑工作区标题 → 当前创作对象 → 工作区 → 操作 → 状态 | 工作台可宽屏增强；手机仍有可用路径，不能改掉真实创作控制 |
| Admin | 后台导航 → 紧凑任务标题 → 筛选/搜索 → 表格/表单 → 结果 | 同一品牌，密度可提高；数据/权限/批量操作不变 |
| 离线/系统失败 | 紧凑状态标题 → 发生什么 → 仍可用内容 → 重试/返回 | 不清掉本地草稿，不伪装为空内容 |

## 8. 全站内容清理方法

一级效果图中的 Logo 可作为品牌区位置参考，尺寸和留白按 2.3 校准；二级及更深截图中的 Logo 与专属留白应移除。组件评审板的文档级标识可以保留，板内产品截图按具体层级处理，不能一律判定无 Logo。

每个页面在改样式前填一张内容表，逐块判断，不用「看着乱」作为删功能的依据。

| 检查项 | 决策 |
| --- | --- |
| 用户在此页要完成什么 | 写成一句具体任务 |
| 当前哪些信息支持判断 | 保留并建立主次 |
| 同一事实是否重复出现 | 合并到最接近操作的位置 |
| 是否只是装饰、假状态或无意义编号 | 移除，不迁进新组件 |
| 是否实际属于别的主 tab | 移至正确归属并保留可理解路径 |
| 是否没有数据/权限依据 | 不上线假功能；说明缺口 |
| 是否是业务必要信息 | 保留或换更清楚的展示，不能为美观删掉 |
| 哪个动作最重要 | 给一个主强调，其余降为次要 |

默认不新增 token/DLC 等尚未开放的未来功能，不把信息架构清理变成业务扩张。

## 9. 页面验收的共同结果

用户能回答：这是哪里、主要内容是什么、当前状态是什么、我能做什么、操作后发生了什么。五个主 tab 使用同一品牌、字体、导航、按钮、列表与反馈语法；页面通过内容层级体现差别，不能五页换五套主题。
