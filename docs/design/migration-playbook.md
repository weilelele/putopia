# UI 迁移与验收手册

版本 2.3 · 2026-09-09 · 从属于 [权威 UI 规范](../design-system.md)。

**本次交付是规范与说明，不是全站改版完成。** 下表是后续工作清单，不代表这些路由已经通过新设计验收。先看 [组件说明](ui-components.md)、[页面模板](page-patterns.md) 和 [导航与交互合同](interaction-contracts.md)。本轮确认的是设计方向和交互合同，尺寸等具体值是实施默认值。

## 1. 改版顺序与完成条件

| 阶段 | 工作 | 可以进入下一阶段的条件 |
| --- | --- | --- |
| P0 基准锁定 | 归档已选图、保护 logo 与设备原图、核对路由和组件、截图当前主要页面 | 能明确每页来源、当前行为、目标模板与差异 |
| P1 基础系统 | 统一字号/间距/颜色角色、Button/Field/Tabs、紧凑标题栏、Quiet Rail、Sidebar；限制 BrandHeader 的适用场景 | UI Kit 以真实字体展示所有基础状态，390px 可用 |
| P2 Dashboard 样板 | Updates 时间轴 + Events 横轨；资料入口归 Voyagers | 最近 10 条规则、横滚/纵滚、状态与导航验证通过 |
| P3 五个主入口 | Intel、Devices、Worlds、Voyagers；共用 P1 组件 | 五页视觉同源，业务模式和归属清楚 |
| P4 次级流程 | 详情、参与、登录、资料、领取、提交 | 端到端行为、权限、草稿、返回、失败和结果完整 |
| P5 其他界面 | Admin、newsletter、公共介绍、工作台、离线与保留 demo | 不残留第二套视觉体系，重要独立流程不受损 |
| P6 收敛 | 删除已无人引用的旧样式/组件，更新 UI Kit 与规范 | 引用检查、回归、检查命令通过；无盲目全仓替换 |

先升级基础组件再迁移页面，不给每个页面复制一套新按钮。一个 PR 聚焦一个可验证的模式或流程；不要用一次无法审查的全站样式覆盖完成任务。

## 3. 每页改版的操作步骤

1. **记录现状**：390×844 截图，主任务、角色、主动作、路由/返回、数据字段、空/错/忙状态。源码存在不等于浏览器效果已验证。
2. **整理内容**：给每个区块标保留、合并、移位、移除装饰；写明理由。业务内容删除需有实际需求依据。
3. **选择模板**：先判定一级/二级/详情/任务/品牌展示场景，按 §1.3 确定页头；登记 ownerTab、实际来源、兜底返回与导航策略；从页面文档挑模式，列出需要的组件，不重新发明视觉语言。
4. **列差异**：例如底栏围框移除、资料移入 Voyagers、假 LIVE 改真实媒体状态；逐项对应代码点。
5. **实施共享变化**：新增必要的中央字号角色，完善状态/语义，再迁移调用方。先读该版本 Next.js 的本地文档再写相关应用代码。
6. **验证行为**：登录/权限、筛选返回、表单草稿、提交防重、失败重试、成功下一步。
7. **对比图像**：相同宽度、内容、状态下比较参考与实际。以规则为准纠正生成图误差，不照抄错误字形、颜色或虚构数据。
8. **记录结果**：更新台账、UI Kit、截图、未完成问题与检查结果，再请求对应实现的评审。

## 4. UI Kit 的目标结构

继续使用现有 `/ui-kit`，不是另建第二个组件库。每个示例标明对应文档章节、实际组件名和实现状态。

| 区域 | 必须展示 |
| --- | --- |
| Foundations | 原 logo、全部规范颜色/字号/间距、可读与不可用的配色组合 |
| Navigation | 一级品牌区 + 必要操作（名称仅 sr-only h1）、二级/详情/任务/弹层紧凑栏，明确路由归属与实际返回；Quiet Rail 五个选中态、Sidebar、子路由归属、Tabs/Filter 差别 |
| Actions | primary/secondary/ghost、长标签、icon-only、focus、disabled、loading |
| Content | 轻列表、普通卡/链接卡、媒体比例、缺图、长标题、时间与元信息 |
| Dashboard | 图文/纯文 Updates、最近 10 条长页面、单/多/空 Events 横轨 |
| Forms | 各输入和选择、帮助、必填、错误关联、readonly、提交中与失败保值 |
| Feedback | 空/无结果/错误/无权限/离线/成功、toast、骨架 |
| Overlays | Dialog、手机 Sheet、键盘/焦点、草稿保护 |
| Product patterns | 设备阶段、世界队列状态、成员列表、讨论与输入、后台表格 |
| Page compositions | 五个根页面 + 一份详情 + 一份参与 + 一份身份/表单模板 |

数据为明确标记的本地 fixture，不连接生产数据库。视觉例子不用假数据伪装实时功能。组件不适用的状态标 N/A；不用为 Divider 人为制造 loading/disabled。

每个组件示例卡记录：用途、API（真实支持）、变体、状态、窄屏行为、语义要求、对应来源、最后验证日期。生成图不代替可交互 UI Kit。

## 5. 验收清单

### 5.1 品牌与视觉

- [ ] 原始 logo 文件和比例未变，未使用代码近似 logo 或生成图截图重建。
- [ ] 五主 Tab 一级页统一克制品牌区；Logs、My Profile 等二级及更深无 Logo；工作台/弹层不重复品牌，欢迎/登录/关于等按用途判断。
- [ ] 二级已移除旧品牌容器、专属留白与分隔线；一级保留品牌区但压缩留白，没有只隐藏图片留下空位。
- [ ] 一级品牌区最小 64px；不显示重复 Tab 标题，不保留标题空位；必要动作命中至少 44px；二级/任务紧凑栏最小 56px；标题 24/20px、动作命中至少 44px，长文/放大可增长。
- [ ] 页面标题只出现一次；详情导航上下文与正文完整标题不重复，一页一个 h1。
- [ ] 顶部安全区不与原生壳重复叠加；Web/PWA/App 使用相同内容结构。
- [ ] 无为了对称新增的菜单/头像/通知；右侧操作来自页面真实任务。
- [ ] 深蓝、品牌橙、灰白与真实语义色分工正确；没有新增灰/青品牌主题。
- [ ] Courier Prime 400/700，所有必要文字 ≥12px，手机输入 16px。
- [ ] 橙底主按钮配深蓝字；弱文字与边界按实际底色检查对比度。
- [ ] 无渐变、光晕、阴影、玻璃、扫描线、装饰 HUD；切角克制。
- [ ] 页边距、区块距、卡片内距来自共享规则；没有厚重框中框。
- [ ] 图片来源与型号正确，缺图/长名不会破版。

### 5.2 信息架构与内容

- [ ] 五个 tab 完整名称与顺序正确，Dashboard 不叫 Home。
- [ ] Dashboard 无 My Profile/头像资料入口；Voyagers 有清楚入口。
- [ ] Updates 有权限过滤、稳定倒序和最多 10 条规则，不能为了凑数造事件。
- [ ] 有图左图右文，无图无空框；不把十条硬塞一个视口。
- [ ] Events 横滑、下一张可见；不是双列网格，不自动轮播。
- [ ] 当前状态、时间、价格、库存、开放条件来自数据，无伪 LIVE/倒计时。
- [ ] 一处决策一个主动作；正文和装饰清理不删除业务信息。

### 5.3 响应式与可操作性

- [ ] 先验 390×844，再验 320/360px、768px、约 1440px 宽屏和手机横屏。
- [ ] 无整页横溢；只在设计指定的轨道/表格局部横滚。
- [ ] 五个导航与所有核心操作可触达，≥44×44px。
- [ ] 安全区、移动地址栏、键盘、200% 放大不遮挡内容或焦点。
- [ ] 主内容只有一个纵滚 owner，模态锁背景，关闭后恢复位置。
- [ ] Tabs/筛选/菜单/表单键盘路径完整，焦点不被切角和固定栏遮挡。
- [ ] 辅助名称、时间完整值、标题层级、错误关联和图片 alt 正确。
- [ ] 减少动态偏好下仍能理解状态，没有必要信息依赖动画。

### 5.4 状态与业务回归

- [ ] 默认、加载、空、无结果、错误、禁用、焦点、完成覆盖适用场景。
- [ ] 鉴权 loading 不闪假访客锁；guest/applicant/voyager/architect 按现有业务验证。
- [ ] 子路由高亮归属正确；跨 Tab 来源返回、直接打开兜底、切 Tab 恢复与重复点击均按交互合同验证。
- [ ] 底栏/固定操作条/键盘/模态按显示与层级矩阵处理，无多重补白或背景焦点。
- [ ] 所有退出入口共享草稿保护，退出账户后不能恢复另一身份输入；存储失败不显示已保存。
- [ ] 超时但服务端已成功、结果无法核对、上传部分失败、队列断线重连有 fixture 覆盖，未知结果不自动重提。
- [ ] 过滤、分页、讨论草稿、表单答案在返回/切换/失败时合理保留。
- [ ] 重复点击不产生重复业务提交；成功结果来自服务端。
- [ ] 局部失败不清除其余已加载内容，重试范围明确。
- [ ] 旧功能和真实数据权限未被视觉组件改变。

## 6. 验证环境与命令

Preview 可能共享生产 Supabase、MongoDB、Stripe。视觉验证优先本地 fixture、纯函数测试和只读路径，不用测试领取/支付/改角色去写共享生产数据。样例不能创建真实订单。需要业务写入验证时使用已确认隔离的测试环境与测试对象。

应用代码实施并准备推送前按仓库要求执行：

```bash
npm run design:check
npx tsc --noEmit
npm run lint
npm test
npm run build
```

纯文档更新检查相对链接、资源完整性、`git diff --check`，并运行适用的 design gate；不以文档改动的成功推断应用通过端到端验证。

自动扫描不能判断构图和品牌细节。每个完成页面保留 390×844 首屏、必要长图、关键状态、宽屏截图；比对同一内容/状态，确认之后再扩大测试范围。
