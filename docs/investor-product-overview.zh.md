## 一、项目是什么

Multiverse Collective 是一款由实体设备与 App 共同构成的科幻硬件游戏。

玩家会获得一台名为 **Multiverse Console** 的实体设备，并通过它持续接收来自不同平行世界的影像、声音、信号和事件。与传统游戏要求玩家进入屏幕中的虚拟世界不同，我们希望让虚拟世界主动进入玩家的现实生活：设备被放置在用户家中，世界按照现实时间持续演化，特殊现象会在特定时间发生，玩家需要亲自观察、记录、判断，并在部分事件中作出回应。

App 是连接玩家、内容、社区与设备的数字层；Multiverse Console 是将这些内容带入现实空间的实体入口。二者共同组成完整产品，而不是两个彼此独立的业务。

一句话概括：

> **一款让虚拟世界通过实体硬件持续进入现实生活的科幻游戏。**

英文核心表达：

> **A sci-fi hardware game where fictional worlds break into real life.**

项目的体验目标不是让用户观看一个已经写完的故事，而是让用户相信自己持有一个真实存在、持续工作的观测终端，并与其他设备持有者共同组成一张庞大的平行世界观测网络。

## 二、产品的核心命题：虚拟世界入侵现实

传统电子游戏通常把玩家带进一个封闭的虚拟空间。玩家启动游戏时，世界开始运行；玩家关闭游戏时，体验暂时停止。

Multiverse Collective 采取相反的方向：

- 游戏的核心入口是一件真实存在于玩家生活空间中的硬件；
- 平行世界中的时间与现实时间同步推进；
- 世界事件可能在预告后的某个现实时间窗口发生；
- 玩家可能错过一次无法原样重现的观测机会；
- 来自不同地区和不同设备的记录可以相互补充、印证；
- App 通知、实体设备、现实地点和区域密度都会成为游戏机制的一部分。

因此，产品的核心体验不是“随时点开一段内容”，而是：

> **某个不属于现实世界的事件，正在通过你家中的设备发生。**

这种设计让科幻世界不再只存在于屏幕之内，而是以持续信号、限时事件、现实地理位置、实体设备和玩家关系的形式渗入日常生活。

## 三、一个产品，两个核心模块

### 3.1 App：组织、内容与社区的数字层

App 对外表现为“平行世界观测组织”的内部网络。它不替代硬件完成核心观测，而是负责把用户、设备、内容和共同参与组织起来。

主要功能包括：

- 完成用户注册、身份建立与成员成长；
- 接收组织通知、事件预警和任务；
- 查阅平行世界、设备、事件与观测档案；
- 查看 Console 的发现、申领、发放、物流和运行状态；
- 参与信号辨认、投票、事件讨论和集体行动；
- 提交个人观察记录、梦境和平行世界构想；
- 浏览其他成员的记录，并追踪内容是否被组织采纳；
- 管理个人持有的 Console、天线与可访问世界；
- 记录用户对事件的贡献，并承载未来的组织 Token 系统。

App 是日常活跃、内容沉淀与人与人连接的主要场所。即使用户没有站在 Console 前，也可以持续了解世界变化、准备下一次观测或参与社区协作。

### 3.2 Multiverse Console：游戏进入现实的实体入口

Multiverse Console 是产品的核心硬件，也是整个世界观中最重要的道具。它是一台带有屏幕、扬声器、旋钮、按钮和可扩展天线接口的实体终端。

它在现实产品中的作用，是把持续更新的数字内容转化为一种具有现场感和仪式感的硬件体验。

网站当前将 Console 的能力归纳为四项。新版材料也应保持这一结构，不再把内容更新、限时事件、Batch 差异和收藏价值误写成彼此独立的设备功能。

1. **世界信号探测｜Worlds Detection / Spatial Signal Detection**  
   Console 可以在不同频率中寻找平行世界信号。每个世界拥有对应的频段和调谐条件；连接建立后，玩家可以选择观测点，实时查看该世界正在发生的影像。

2. **跨时空音频｜Audio Collection / Transtemporal Audio**  
   Console 可以接收当前观测世界中的环境声音、语言、音乐和其他音频，也可以消耗量子能量，将音乐或声音内容发送至目标世界。

3. **量子能量释放｜Quantum Discharge**  
   Console 可以向目标世界释放一股量子能量。不同世界可能产生不同反应：有些不会出现明显变化，有些则可能因此发生重要事件。该功能需要能量匣提供或补充能量。

4. **内在声音接收｜Inner Voice**  
   这是与量子按钮相关的深层连接功能。在部分设备上，量子释放会同时启动音频捕捉，将当前世界的声音发送到平行世界；如果另一端存在智慧生命，Console 可能接收到以思想、低语或感知形式返回的回应。

这四项能力共同构成“发现世界—接收信息—向另一端施加输入—获得回应”的完整链路。网站当前将前两项标记为 `ACTIVE`，量子能量释放标记为 `DEV`，内在声音标记为 `UNKNOWN`；投资人材料可以保留这种状态差异，清楚说明哪些能力是基础层、哪些仍处于开发或探索阶段。

Console 同时保留模块化扩展接口，用于连接能量匣、天线和其他接收组件。模块化扩展属于硬件平台与商业模式，不需要被拆成第五项核心功能。

## 四、获得设备之后，玩家究竟怎么玩

目前产品已经对“设备和组织是什么”以及“如何获得设备”进行了较充分的设计。下一阶段更重要的问题是：用户拥有 Console 以后，为什么会长期回来，它如何成为一款持续运行的游戏。

Console 持有后的玩法可以分为四个层次。

### 4.1 日常观测

玩家可以在日常生活中打开设备，调谐当前可用的世界与频道：

- 查看新的影像、声音和信号片段；
- 记录出现时间、频率、画面和异常现象；
- 对模糊内容作出判断或分类；
- 将记录上传至 App，与其他玩家的观测进行对比；
- 追踪同一个世界在数日、数周甚至更长时间内的变化。

日常观测构成低门槛、可持续的基础玩法。它不要求每次都有重大剧情，而是让设备保持“另一边仍在发生事情”的生命感。

### 4.2 世界事件

世界事件是所有或大多数设备都能接收到的大型共同事件。

其中一部分事件会提前发出预警，告知玩家某个世界将在特定时段出现异常现象。事件发生时，玩家可以在自己的 Console 上同步观察，记录所见内容，或者通过设备与事件互动并获得进一步信息。

世界事件让整个玩家群体在同一个现实时间面对同一件虚拟事件，形成共同在场和共同观测的体验。

### 4.3 区域事件

区域事件由现实地理位置与当地设备网络触发。

当某个城市或区域内的 Console 达到一定数量或密度后，该区域会触发并发现新的特殊事件。

这个机制把现实中的设备分布直接转化为游戏条件。新增设备不仅意味着新增用户，也意味着观测网络增加了新的节点，并可能让一个区域首次满足事件触发条件。

### 4.4 事件中的互动

玩家不只负责观看。在部分事件中，玩家可以使用 Console 已定义的能力接收声音、发送音频、释放量子能量或尝试建立更深层的连接，并从另一端获得新的信息。

具体事件允许哪些操作、会产生怎样的结果，由该事件本身决定。本文不预设额外的互动形式。

## 五、人与人如何形成观测网络

单台 Console 是一个观察窗口；所有 Console 联结在一起，才构成完整产品。

整个玩家网络可以理解为一张分布在现实世界中的观测阵列：

- 每一台设备都是一个观测节点；
- 公共事件让所有节点同时面对同一现象；
- 区域事件让地理上接近的节点形成局部网络；
- 单个玩家的记录可以被其他玩家印证或补充；
- App 将分散的观测汇总成组织档案；
- 玩家由此获得共同发现、共同解谜和共同见证的体验。

人与人之间的连接并不依赖传统社交产品中的关注关系或即时聊天，而是围绕一个共同对象建立：大家在观察同一个正在变化的世界。

玩家关系可以自然分为几个尺度：

- **个人尺度**：我看见了什么，我的设备有什么不同；
- **小组尺度**：同一地区或同一 Batch 的玩家如何互相补充；
- **全局尺度**：所有设备如何共同记录一次世界事件；
- **长期尺度**：不同时间加入的玩家如何共同维护一个不断扩张的世界档案。

这种设计同时保留个人设备体验和共同观测体验：每个人通过自己的 Console 进行观察，分散的记录再通过组织网络汇集起来。

核心表达可以是：

> **一台设备让玩家看见另一个世界；一张设备网络让所有人共同理解它。**

## 六、梦境与平行世界记录：独立的 UGC 内容模块

梦境和平行世界记录不属于 Console 事件玩法本身，而是一套独立的、持续运行的 UGC 内容创造模块。

用户可以在 App 中提交：

- 梦境记录；
- 对某个平行世界的构想；
- 日常生活中观察到的异常现象；
- 第一人称的观测日志；
- 图片、声音、视频或其他辅助材料；
- 对已有世界的补充解释和支线内容。

这些内容首先进入组织的待审查或待调谐阶段。团队和社区可以进一步筛选、讨论、辨认和发展其中有潜力的部分。

一条用户记录可能经历以下过程：

> 用户提交初始记录  
> → 组织筛选并建立调查  
> → 社区参与信号辨认或内容补充  
> → 编辑团队完成世界设定与素材制作  
> → 正式进入世界档案  
> → 成为 App、Console 或未来事件中的内容

因此，UGC 不只是社区展示内容，也可以成为新世界和新故事的早期来源。但它不会未经控制地直接进入正式设定，所有进入核心体验的内容仍需经过筛选、编辑和世界观一致性管理。

这套模块提供了另一种参与方式：即使用户暂时没有持有 Console，也可以通过记录、想象和投稿参与世界建设。

## 七、内容如何被持续生产

Multiverse Collective 的内容系统由 PGC 与 UGC 共同组成，但二者承担不同职责。

### 7.1 PGC：保证世界质量与持续推进

由官方团队生产和控制的内容包括：

- 核心世界观、规则与组织叙事；
- 主要平行世界、角色和长期故事线；
- 世界事件、区域事件和限时观测窗口；
- Console 接收的影像、声音与信号素材；
- 设备 Batch 的发现、修复、发放和运行故事；
- 任务、谜题、互动节点与事件结果；
- 对 UGC 的筛选、编辑、再创作和正式归档。

PGC 的价值在于保持内容质量、审美统一、更新节奏和长期叙事方向。

### 7.2 UGC：扩大世界、视角与参与深度

用户贡献的内容包括：

- 梦境和平行世界构想；
- 观察记录与第一人称日志；
- 世界事件和区域事件的现场记录；
- 对异常信号的判断与解释；
- 图片、视频、声音和现实地点材料；
- 投票、选择与集体行动结果。

UGC 让玩家从内容消费者变成世界的发现者、记录者和共同作者。

### 7.3 编辑层：把开放参与转化为可控世界

PGC 与 UGC 之间需要一个明确的编辑与审核层：

- 判断哪些记录值得继续发展；
- 合并相互关联的用户线索；
- 保证正式内容符合世界观与质量标准；
- 将优秀 UGC 改编为世界档案、信号任务或事件；
- 记录内容来源，并按照未来确定的规则处理相应贡献。

最终形成的不是一个无边界的投稿社区，而是一套由官方维护、由用户不断提供新线索的共同世界生产系统。

## 八、Token：对有效观测与贡献的反馈机制

未来产品计划引入组织内部 Token。用户完成某些特定环节或场景的观测，并将有效记录上报给组织后，可以获得一定数量的 Token。

Token 用于记录和反馈用户对观测工作的贡献。除这一基础作用之外，未来还可能具有其他用途，但具体用途目前尚未确定，因此本文不作进一步展开。

---

## 九、实体化 DLC：可更换天线

Console 将通过可更换天线获得新的观测能力。天线不是普通装饰配件，而是实体化的内容入口和 DLC。

不同天线对应不同平行世界的信号。玩家将天线连接到 Console 后，就可以观测该天线对应的世界内容。

天线可以形成两类商业产品：

### 9.1 天线订阅

用户可以通过订阅方式持续获得新的天线，从而接入新的平行世界。

### 9.2 精品天线

除订阅之外，团队也会提供设计和制作更精致的精品天线，供用户单独购买。

天线把传统数字游戏中的 DLC 转化成一件可以安装在 Console 上的实体内容入口，也构成硬件售出之后的持续内容与收入来源。

核心表达可以是：

> **每一支天线，都是通往另一个世界的实体 DLC。**

## 十、完整玩家旅程

### 10.1 获得设备之前

1. 用户通过广告、内容或异常信号接触到组织；
2. 在 App 中注册并建立身份；
3. 查阅世界与设备档案；
4. 提交梦境、世界记录或参与社区任务；
5. 追踪某个 Console Batch 的发现与修复过程；
6. 支付定金或完成申领，获得设备配额；
7. 在等待期间持续收到 Batch 内容、实体材料和组织通知。

### 10.2 获得设备之后

1. 激活个人 Console，并将其绑定到 App 与设备档案；
2. 接入公共世界，开始日常观测；
3. 接收世界事件预警，并在规定时间参与；
4. 上传记录，与其他设备的结果互相印证；
5. 参与本地设备网络触发的区域事件；
6. 因有效观测、记录或协作获得组织 Token；
7. 通过新的天线接入更多世界和内容；
8. 持续积累个人观测记录，并参与组织内的共同观测。

用户购买硬件不是旅程的终点，而是从“观察组织”转变为“成为观测网络节点”的开始。

## 十一、内容与玩法循环

完整循环可以概括为：

> 官方建立世界与事件  
> → App 发出任务和预警  
> → Console 呈现信号与现象  
> → 玩家观察、互动和记录  
> → 多台设备的结果在 App 中汇总  
> → 团队筛选 UGC 并推进世界  
> → 新内容、新事件和新天线重新进入系统

在这个循环中：

- PGC 保证世界的质量、方向与持续更新；
- UGC 提供新的世界、视角、记录和参与结果；
- App 负责组织、沉淀和连接；
- Console 提供现场感和实体操作体验；
- 世界事件制造全体玩家的共同时间；
- 区域事件把现实地理位置转化为游戏条件；
- Token 记录玩家的长期贡献；
- 天线持续扩展可以被观测的宇宙。

这使产品同时具备硬件产品、持续运营游戏、内容平台和社区网络的属性，但所有部分都围绕同一个核心行为展开：观察并理解另一个正在持续发生的世界。

## 十二、商业模式

### 12.1 Console 硬件销售

Console 是第一次高价值转化，也是用户进入完整体验的门槛。不同 Batch 可以拥有不同来源故事、外观处理、编号、档案与内容权限。

### 12.2 天线订阅

通过订阅方式向用户持续提供新的天线，形成硬件售出后的持续收入。

### 12.3 精品天线

以更精致的设计和制作提供可单独购买的天线产品。

商业模型的核心不是一次性销售一台设备，而是：

> **用 Console 建立高价值入口，用持续发生的世界维持长期参与，再通过实体化内容扩展产生持续收入。**

---

## 十三、产品的长期价值

Multiverse Collective 的长期价值来自几个彼此增强的网络效应。

### 13.1 设备网络效应

设备越多，现实世界中的观测节点越多，可以触发的区域事件越丰富，多节点协作也越有意义。

### 13.2 内容网络效应

世界和事件越多，玩家可以观察、讨论和贡献的对象越多；玩家贡献越多，团队可以发展的世界线索也越丰富。

### 13.3 社区网络效应

玩家不只是因为认识彼此而连接，而是因为共同见证过一次事件、共同解开一个信号或共同建立了一个世界而形成关系。

最终，Multiverse Collective 希望建立的不是一台孤立的科幻设备，而是一张不断扩张的现实观测网络：每一位用户、每一台 Console 和每一支天线，都让这个虚拟宇宙在现实世界中拥有更多入口。

---

## 十四、对外表达时必须保持清楚的边界

为了让投资人准确理解项目，新版材料需要明确区分以下三层：

### 已经建立的基础

- App 与组织内部网络；
- 用户身份、世界档案和社区内容结构；
- 设备 Batch 的发现、申领、发放与内容体系；
- 世界上报、信号辨认、投票、日志和审核发布；
- 初步用户获取、注册与设备定金验证。

### 正在形成的核心产品

- 可实际交付的 Multiverse Console；
- 设备与 App 的绑定；
- 通过设备接收和调谐持续内容；
- Console 持有后的日常观测循环；
- 世界事件及多设备共同参与。

### 未来规划

- 基于现实设备密度触发的区域事件；
- 更复杂的硬件互动与跨世界输入；
- 组织 Token 与贡献奖励体系；
- 可更换天线及实体 DLC 商业模式。

这种区分不会削弱项目愿景，反而能够让投资人更清楚地看到：团队已经验证了什么、正在构建什么，以及后续增长来自哪里。

## 十五、最终核心表述

Multiverse Collective 不是一台播放科幻内容的设备，也不是一个以神秘组织为主题的普通社区。

它是一款以实体 Console 为核心、由 App 连接、由 PGC 与 UGC 持续生产内容的科幻游戏。玩家通过个人设备观察持续演化的平行世界，通过世界事件和区域事件与其他设备持有者形成共同观测网络，通过记录、互动和创作参与内容的发展，并通过天线接入更多平行世界。

硬件让虚拟世界进入现实；App 让分散的玩家成为组织；内容与事件让整张网络持续运转。

> **我们销售的不只是一台设备，而是一个真实存在于玩家生活中的平行世界入口。**
