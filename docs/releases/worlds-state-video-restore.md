## 范围

2026-09-02 用户明确将 Worlds 与 Device 的播放方案分开：

- Worlds 使用原 Console/Cosmo channel 中的短视频，按 Dreamcatcher 的真实设备状态播放。
- Device 保持 `LIVE FEED NOT CONNECTED`，不恢复旧 Device 播放器，不接入 OBS、不配置流地址。
- 保留已有后台创建、编辑、上下线以及队列归属规则；没有为了演示修改设备状态、提交梦境或重新上线隐藏设备。
- Signal Dispatch 生成、暂停/恢复调度、通知规则不变。后续用户确认的 Live Chat 和导航迭代见下文。

## 播放规则与可靠性

1. 页面打开时按当前状态进入休息或工作循环；已在 processing 的设备直接进入工作循环。
2. 从休息变为工作：播放一次“进入工作”，随后循环工作视频。
3. 工作结束：播放一次“结束工作”，随后循环休息视频。
4. 过渡片段播放中收到状态变化，不打断片段；播完按最新设备状态继续。缺少或撤下过渡素材时跳过，避免停死。
5. 同类素材多于一条时，45–90 秒触发一次原有约 920ms 的短暂重连效果，在中间切换下一条；单条素材保持原生循环，不每圈重载。
6. 复用保留在样式表内的原画面干扰效果，只应用于 Worlds 视频区域。减少动态效果偏好关闭动画。
7. 切换设备重置播放器；30 秒业务状态刷新与每秒本地时间更新不重启稳定片段。
8. 手机内联、静音自动播放；自动播放被拦截可手动 PLAY；可暂停，暂停不会因轮播而取消。隐藏页面暂停播放与素材轮换；加载失败显示提示和 RETRY VIDEO。
9. 预加载下一条同类视频；素材元数据服务器缓存 60 秒，视频由原素材地址直接交付浏览器，不经 Next.js 代理视频字节。

## Live Chat 与导航迭代

- 用户确认原素材改给 London；Worlds 的右侧 ALL 改成明显的 `ARCHIVE / ALL WORLDS` 链接，指向 `/worlds`。删除重复的标题栏 Archive 链接与 All 弹窗；全部已公开设备仍可在横向 tab 栏切换。
- Queue 整行改成真实链接，直接打开既有 `/worlds/[worldId]` 详情，不再弹出简化的 Queue Record。Signal Dispatch 候选视频选择弹窗不变。
- 移除固定 NPC 示例；每台 Dreamcatcher 使用独立的 `comments` 线程（`subject_type=dreamcatcher`，`subject_id=设备 UUID`）。沿用已上线的留言表，不需要新迁移或打开浏览器直写权限。
- 普通登录用户可发纯文本；游客可读并看到登录入口。身份由服务端 session/profile 决定，不允许传入冒充作者、附件或回复目标；本次不触发回复邮件/推送。
- 服务端与输入框均限制 2000 字。服务端通过已持久化留言做同一用户/设备 5 秒的基础冷却检查；它是 best-effort 检查，不是并发原子限流。大规模公开流量前应补专用防滥用策略。
- 作者可删除自己的留言，architect 可管理留言，复用原权限校验；删除使用页面内确认。
- GET 读取 `created_at DESC, id DESC`，每页 50 条，按时间从近到远排列；历史分页保留数据库微秒精度，游标严格校验。
- 只在 Live Chat 打开且页面可见时每 10 秒自动更新最新页；历史页不被刷新顶走，可返回最新。提交成功立即显示真实返回记录，失败保留草稿并显示错误；旧请求不会覆盖新发送/删除结果。
- 房间读取/发送校验设备仍公开；读取响应不缓存。不修改现有留言表 RLS，不将 service-role 凭据交给浏览器。复核依据：[Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。
