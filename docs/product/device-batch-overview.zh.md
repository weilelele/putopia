# Batch 基础信息概述

本文用于准备和维护设备 Batch 的介绍、购买信息与 Updates，帮助用户了解这批设备是什么、从哪来、现在在哪，以及能否购买、买到什么。

## 1. Batch 的定位

Batch 是一批具有共同来源和外观的 Multiverse Console。每个 Batch 的介绍围绕设备本身展开，讲清来源、特点、当前所在地和情况。

组织的来历、平行世界的规则、Voyager 的身份与共同活动，由公共世界观和公共内容承载，见[世界观总览](../game-design/00-overview/zh.md)。

## 2. 基础 Info

| 信息 | 内容 |
|---|---|
| 名称与编号 | Batch 的名称与编号，在各处保持一致。 |
| 设备特点 | 外观、材质、已知的使用特点，以及具体可辨认之处。 |
| 来源 | 在哪里发现或取得，以及已知的来源经过。 |
| 当前所在地 | 当前存放、整理或修复的城市与场所类型。 |
| 当前情况 | 设备的保存状态，以及目前正在进行的工作。 |
| 负责人 | 负责这批设备的成员姓名与职责。 |
| 图片 | 展示设备和场所的图片，注明实拍、设计参考或生成示意。 |

基础介绍建议写成一至两小段，用具体、自然的语言串起这些信息。
同一 Batch 内的 Console 保持共同外观；个人编号和使用记录可以不同。

来源与当前所在地分别确认和填写。例如，一批设备在京都被发现，后来转移到另一座城市整理，介绍中应分别说明这两个地点。
待补充的信息在编辑稿中标明；公开介绍中的未知事项写明尚未确认，来源推测注明判断依据。

## 3. 购买信息

开放购买时，在基础介绍之外单独列明：

- 总价、币种、付款方式，以及运费和税费是否包含。
- 本批可售数量与当前可购买情况，以实际库存为准。
- 购买后实际获得的内容；如分多个包裹，列明每包内容和 Console 本体所在的包裹。
- 现货或预售、预计发货时间；日期待定时写明尚未确认。
- 配送范围、取消与退款规则、售后联系方法。

购买信息使用当前已确认的运营资料，包裹安排与交付说明对应实际销售承诺。
关注用于接收后续消息，购买状态以订单确认为准。批次整体进度与个人订单物流分别说明。

## 4. Updates 手动发布

有新情况时，由负责人或管理员撰写、核对并手动发布。更新节奏跟随实际进展。

一条 Update 包含日期、明确的标题和具体进展，可附相关照片或视频。
涉及购买者时，说明对他们的影响，以及是否需要采取行动。

适合发布的内容包括：设备转移地点、整理或测试结果、新的设备照片、包裹内容确认、开始发货或发货时间调整。

发生延期时，交代原计划、调整后的时间或待确认状态、原因及下一次说明时间。
编辑完成后保存草稿，核对后发布到公开页面；需要通知关注者时，按邮件规则单独发送。
后台操作见[人工发布说明](../releases/device-manual-publication.md)。

## 5. 填写模板

以下模板用于整理编辑底稿。页面上将基础介绍与购买信息分开呈现。

```text
Batch 名称 / 编号：
设备特点：
来源 / 发现地点与经过：
当前所在地：
当前情况 / 正在做什么：
负责人：
图片与说明：

基础介绍：
将上述信息整理成一至两小段，明确说明已知情况和待确认事项。

购买信息（开放购买时填写）：
价格与费用：
可售数量 / 当前可购买情况：
实际包含内容 / 分包安排：
现货或预售 / 发货时间：
配送、取消退款及售后：
```

发布前核对：介绍具体清楚，来源与当前位置准确，事实与推测区分明确，购买信息与运营资料一致。
